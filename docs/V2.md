# Peregrine — Version 2 plan

Features agreed for v2. Nothing here is built yet; this is the spec to implement
from. Everything must hold Peregrine's invariants: local-first, BYO model, the
egress guard + Activity Log for anything that leaves the machine, and
**profession-neutral** — every feature works for a nurse, teacher, or tradesperson,
not just engineers.

---

## 1. Assistant modes — Senior / Thinker / Companion / Helper

Today there's one persona ("Senior <profession> mode"). v2 turns that single sidebar
card into a **live switcher** across four modes. Each mode is a different *stance* —
the voice and behavior change, the grounding and no-invention rules never do. All
four stay shaped by the user's profession and seniority.

| Mode | Stance | Sounds like | Best for |
|------|--------|-------------|----------|
| **Senior** *(current)* | Seasoned mentor: direction, critique, standards | "Here's how I'd structure it — and the trap most hit first." | leveling up, honest critique |
| **Thinker** | Reasons *with* you: questions, options, tradeoffs, devil's advocate | "What's the one constraint everything else bends around?" | decisions, strategy, untangling |
| **Companion** | Warmth + momentum: support, celebrates wins, gentle accountability | "That stuck feeling is normal — let's find one small step." | rough days, accountability |
| **Helper** | Pure execution: minimal talk, hands back the artifact fast | "On it — here's a draft you can edit." | churning through tasks |

### Behavior
- Each mode is a **system-prompt layer** on top of the existing profession/seniority prompt.
- The mode is **global** (one active mode app-wide), swapped from the sidebar switcher; choice **persists in the vault** (new `chat_mode` setting).
- Applies to the **senior chat** first; the **debrief** inherits it. Meetings and résumé stay task-focused regardless.

### Auto-suggest (opt-out, never automatic)
- When the conversation clearly fits another mode, Peregrine surfaces a **one-line chip** in the chat — e.g. "Sounds like a heavy one — switch to Companion?" with **Yes / not now**. It only *offers*; the user flips it.
- **Rare and quiet:** at most one nudge per stretch, dismissible, backs off when declined — no repeating, no counter, nothing boss-facing (avoids the surveillance/nagging failure mode of tools like 15Five).
- **Detection** is done by the model itself (it already sees the conversation) — a tired/frustrated tone → Companion, a big fork → Thinker, "just draft it" → Helper. No new tracking; nothing stored beyond the user's choice.
- **Off switch:** a single "suggest modes for me" toggle in Settings, on by default.

### Build surface
- 4 prompt templates; `chat_mode` in `settings.rs`; sidebar card → switcher component; the suggest chip in the chat; the Settings toggle.

## 2. News ingestion & synthesis — a role-aware briefing

A pipeline that turns professional sources into a role-aware, **multi-column briefing**
of "why this matters to *you*" cards. Built **natively in Rust behind the egress guard**,
taking only non-conflicting *ideas* from two projects:
- **Front half — sources & resilience** from `Agent-Reach`: its menu of **low-risk
  sources** and its **"primary + fallback per source, with a health check"** pattern.
- **Back half — how stories are organized** from `Agently Daily News Collector`
  (Apache-2.0): an LLM **outline** into columns, an LLM **shortlist** per column, and a
  **multi-column** layout — reimplemented in Rust, without its Python framework or its
  headless-Playwright browser (we use lightweight readability instead).

The conflicting parts (Python/framework dependencies, a bundled browser engine, and
login/cookie/scraping platforms) are dropped — see "Deliberately excluded" below.

### Sources — no login, no scraping, no ToS-gray platforms
All fetched with `reqwest` (already a dep) through the **egress guard**, recorded in the
**Activity Log**, **disabled in Airtight** trust mode, and off by default until the user
enables them. Keyword-driven and profession-neutral throughout.
- **Google News RSS search** — `https://news.google.com/rss/search?q=<keywords>%20when:7d&hl=<lang>&gl=<country>&ceid=<country>:<lang>` (recency + locale from settings); resolve the `news.google.com` redirect to the real article URL.
- **Any RSS / Atom feed** the user adds — profession-agnostic (a nurse's journal, a teacher's ed blog, a trades newsletter, an engineer's release feed).
- **Open web / article readability** — for an openly readable article, fetch it and run a Rust readability pass to get clean body text. If it's paywalled or blocks us, skip it — never fight it.
- **YouTube captions** — pull a video's transcript (captions only, no download) and summarize a talk in the user's field.
- **Podcast → text** — transcribe an episode with the **on-device Whisper already in the app**, then summarize.

### Stage 0 — Outline (optional, one LLM call)
- From the user's interests, the model proposes **2–4 "columns"** — the briefing's sections, each with its own search keywords (e.g. a nurse's *Patient safety · Staffing & policy · Clinical research*; every profession gets its own). Structured output (a list of `{column, keywords}`), never freeform.
- **Optional and cheap.** If disabled (a "cheap mode"), the briefing is a single flat column from the raw interests with no model call. The model may only shape topics the user's keywords already imply — it never invents an interest.

### Stage 1 — Fetch
- Query per column (Stage 0's keywords) when columns exist, otherwise from the user's **profile keywords** (profession + a user-editable "interests" list). Never hard-code engineer terms.
- Fetch each enabled source above; parse RSS/Atom in Rust (`feed-rs` / `quick-xml`).
- Only the keyword queries and the URLs the user pointed at leave the machine — no vault data — and every outbound host is disclosed in the Activity Log.

### Resilience & health (Agent-Reach's pattern, kept)
- Each source has a **primary + fallback** fetch path; if the primary fails, fall back and mark the source *degraded* rather than failing the whole briefing.
- A **"connections health"** panel in Settings (its `doctor` idea): one click shows which sources are reachable, which are degraded, and how to fix.

### Stage 2 — Dedup & filter
- Feed items carry: title, link, publish date, description, source.
- **Group near-identical stories** from multiple outlets into one item (title similarity — e.g. normalized token overlap / Jaccard over a threshold).
- **Drop** anything older than the window, or below a **relevance threshold** scored against the user's profile keywords (keyword overlap in title+description; keep it cheap and local — no model call in this stage).

### Stage 3 — Shortlist & synthesize
- **Shortlist (LLM, optional):** per column, the model picks the best **N** stories from the filtered set — curated, not just recency-sorted. Structured output (indices/ids only), so it can't invent stories that weren't fetched.
- **Synthesize:** for each shortlisted item, send **title + description — plus the readability body when we cleanly got one** (headline+description alone when we didn't) to the user's **chosen model** via the existing `model::send` egress-guarded path. Never fight a paywall to get a body.
- Prompt produces: a **short professional summary** (one paragraph) + **one "why it matters to someone in this role" line**, grounded strictly in the provided text, no invention. Profession-aware via the same `{profession}`/`{seniority}` context.
- Both outline and shortlist are optional LLM steps — the "cheap mode" skips them and ranks locally (keyword overlap × recency).

### Stage 4 — Deliver (multi-column briefing)
- Assemble a **multi-column briefing** — the columns from Stage 0, each with its curated, synthesized **cards** (title, one-paragraph summary, why-it-matters line, source name, resolved link). Falls back to a **single flat ranked list** when the outline is off (cheap mode).
- Rank within a column by relevance × recency.
- **Cache per user for a few hours** (store the assembled briefing + a fetched-at timestamp in the vault or a local cache file; serve from cache within the TTL) so scrolling doesn't re-fetch or re-summarize. Manual "refresh" allowed.
- New **Briefing** screen laid out as columns; a card opens its resolved link via the opener plugin, and can **"save to memory"** when a story is relevant to the user's own work — feeding the same career vault everything else uses.

### Deliberately excluded (the conflict, removed)
To protect the clean-install and Airtight promises, the briefing does **not** include:
- **Python/framework dependencies** — the `Agent-Reach` CLI and the `Agently` framework. Peregrine ships with no runtime deps to install; a Python requirement breaks "runs on anyone's computer, no admin."
- **A bundled browser engine** — Agently uses headless Playwright to fetch article bodies. We use a lightweight Rust readability pass instead: no Chromium, no scraping heft, and we simply skip pages that block us.
- **Login / cookie / scraping-gated platforms** — Twitter/X, Reddit, LinkedIn (beyond a public reader), Instagram, XiaoHongShu. ToS-gray, fragile, and they'd expand the trust surface far past "nothing leaves except what you point at."
- **Any opt-in "connector"** that routes traffic outside the Rust egress guard / Activity Log. If a user wants those sources, they run such a tool themselves; Peregrine doesn't broker it.

Only the native, no-login, egress-guarded sources above ship.

### Build surface
- Rust: an `outline` step (model) → per-column, per-source fetchers (RSS/Atom, readability, YouTube captions, podcast→Whisper) each with a primary+fallback path; local `dedup`/relevance; a `shortlist` step (model); `synthesize` (model); a cache keyed by source-set+keywords+locale+columns with a few-hours TTL; a `connections_health` command. Settings: interests list, locale, window, per-source enable toggles, **columns on/off (cheap mode)**, connections-health panel. Frontend: multi-column Briefing screen.

### Open questions
- Where to surface it — a dedicated **Briefing** screen, or fold into Today / a morning brief?
- **Cost default:** outline + shortlist add a few model calls per briefing. Default to the richer multi-column mode, or default to the cheap local-only mode and let the user opt up?
- Article-body reading: resolve/read every item up front, or lazily only when a card is opened (cheaper, but the "why it matters" line is then headline-only until opened)?
- How many columns by default (2–4), and can the user pin/rename them?
